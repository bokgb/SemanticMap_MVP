# 現在地からの配達ルート

手紙を書く流れは変更しない。「歩いて探索」では、手紙の後に現在地に近いコンビニ・公園・鉄道駅を選ぶ。到着は本人が確認する方式を保ち、GPSによる到着制限は追加しない。

## 地点データと選び方

- 既存の `spotsData.json`（10,872件、約1.2MiB）を使用する。対象は `convenience`・`park`・`station`。薬局などは今回のルートに使わない。
- 歩いて探索するときに、サイトから地点ファイルを一度読み込む。読み込んだ地点と現在地をブラウザー内で比較する。Overpassや他の外部地点検索APIは呼ばない。
- 出発時の現在地からの直線距離で、各種類の最も近い登録地点を選ぶ。丸める前の距離で比較する。道順・徒歩時間・入口までの距離を計算する機能ではない。
- 最初は半径3km。足りない種類があれば、利用者の操作で半径10kmまで広げる。同じファイルを再ダウンロードしない。
- 3種類がそろってからルートを開始する。範囲外の遠い地点へ飛ばしたり、存在しない場所を作ったり、OICへ戻したりしない。見つからない場合は、その場で体験できる。
- 名前がない地点や「未知地点」は、日本語の「コンビニ」「公園」「駅」で表示する。名前のある地点も画面に出す前にエスケープする。
- 出発地点と3つの目的地を進行データに保存する（ルート `version:2`、`source:spotsData`）。途中の移動やページ更新では目的地を変えない。旧オンライン検索試作のルートは再選択する。

## 位置情報と既存の遊び方

現在地は明示的な操作で取得し、近くの地点を選ぶためにブラウザー内で使う。地点検索のための座標送信はしない。背景の地図タイルの取得には通信が必要で、写真識別は従来どおりGeminiを使う。

「その場で体験」は、コンビニ・公園・駅という物語の場面で進める。特定の実在地点の地図やGPSを必要としない。位置情報の許可拒否・取得失敗・大きな位置誤差・データ読み込み失敗時も、再確認か原地体験を選べる。

駅の写真は都市を限定せず、鉄道駅の駅名看板を対象とする。アンケートは駅で手紙を渡し終えてから表示する。

## 衣笠周辺での確認

参考位置 `35.0325428, 135.7240146` から、現データでは次の地点を選ぶ。

| 種類 | 地点 | 直線距離 |
|---|---|---:|
| コンビニ | 至徳館購買部 | 約111m |
| 公園 | 小松原児童公園 | 約416m |
| 駅 | 等持院・立命館大学衣笠キャンパス前 | 約523m |

実際のプレイヤーの位置で選択結果は変わる。現在のデータは全国をカバーせず、営業状況・入口・通路の正確さも保証しない。

## 確認方法

- `node scripts/verify-nearby.js`：実データの読み込みから衣笠・大阪の地点選択、駅までの進行、保存・復元、未掲載地域、範囲拡大、権限拒否、読み込み失敗・中止、小画面を確認。GPSと写真識別のみテスト用の応答を使用する。
- `node scripts/verify-classroom.js`：手紙と原地体験の既存の流れ。
- `node scripts/verify-before-play.js`：初回案内と権限設定。
- `npm run preview:mobile`：`screenshots/mobile-preview.html`。衣笠の例では現在地だけを仮設定し、既存の実データから地点を選ぶ。

OSM由来の地点データと地図の出典表示は維持する。地点ファイルを更新する場合は、出典・取得日・地域範囲も一緒に記録する。
