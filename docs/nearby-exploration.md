# 現在地からの配達ルート

手紙を書く流れは変更しない。「歩いて探索」では、手紙の後に現在地に近いコンビニ・公園・鉄道駅を選ぶ。到着は本人が確認する方式を保ち、GPSによる到着制限は追加しない。

## 地点データと選び方

- 既存の `spotsData.json`（10,872件、約1.2MiB）を使用する。対象は `convenience`・`park`・`station`。薬局などは今回のルートに使わない。
- 歩いて探索するときに、サイトから地点ファイルを一度読み込む。読み込んだ地点と現在地をブラウザー内で比較する。Overpassや他の外部地点検索APIは呼ばない。
- 出発時の現在地からの直線距離で、各種類の最も近い登録地点を選ぶ。丸める前の距離で比較する。道順・徒歩時間・入口までの距離を計算する機能ではない。
- 最初は半径3km。足りない種類があれば、利用者の操作で半径10kmまで広げる。同じファイルを再ダウンロードしない。
- 3種類がそろってからルートを開始する。範囲外の遠い地点へ飛ばしたり、存在しない場所を作ったり、OICへ戻したりしない。見つからない場合は、その場で体験できる。
- 名前がない地点や「未知地点」は、日本語の「コンビニ」「公園」「駅」で表示する。名前のある地点も画面に出す前にエスケープする。
- 出発地点と3つの目的地を進行データに保存する（ルート `version:2`、`source:spotsData`）。途中の移動やページ更新では目的地を変えない。旧オンライン検索試作のルートは再選択する。

## 位置情報と既存の遊び方

現在地は明示的な操作で取得し、近くの地点を選ぶためにブラウザー内で使う。地点検索のための座標送信はしない。背景の地図タイルの取得には通信が必要で、写真識別は従来どおりGeminiを使う。

「その場で体験」は、コンビニ・公園・駅という物語の場面で進め、地図も表示する。実際の移動やGPSの許可は不要。既に選んだ配達ルートがあれば同じ地図を使い、位置もルートもない場合は大阪・京都周辺の広域参考地図を表示する。その際、現在地や近くの配達先を作り出して表示しない。位置情報の許可拒否・取得失敗・大きな位置誤差・データ読み込み失敗時も、再確認か原地体験を選べる。

開始ボタンではラジオボタンの選択値を直接読み取る。モバイルブラウザーがchangeイベントなしで選択を復元した場合も、選んだ体験方法を手紙から探索まで引き継ぐ。

駅の写真は都市を限定せず、鉄道駅の駅名看板を対象とする。アンケートは駅で手紙を渡し終えてから表示する。

## 地図と詳細パネル

歩いて探索する移動中は、地図を広く表示し、下のパネルには次の地名と到着ボタンだけを出す。上に引くか「詳細」を押すと会話と設定を開き、下に引くか「閉じる」で戻せる。詳細が長い場合は本文だけがスクロールし、上の操作と到着ボタンは固定する。

地図の左上は「つぎの目的地」と現在の段階を表示し、コンビニ→公園→駅の順に大きな地名とアイコンを切り替える。駅は途中では「お届け先」として小さく表示し、駅の段階では大きな主表示にする。実在のルートがない原地体験では、現在の場面名と移動不要の案内を表示する。登録された実際の地名を使い、駅名には必要に応じて「駅」を付ける。「ソラ」などの登場人物名や最初の手紙の完了マーカーは地図に出さない。

進行中の地図には現在の目的地と最終駅だけを表示し、未来の公園や済んだ立ち寄り先は隠す。点線も現在の目的地までのつながりだけを示す。詳細を開いた時と次の段階に進んだ時は、目的地をパネルに隠れない位置へ合わせる。駅マーカーや小さな「お届け先」を先に押すと、同じポコの吹き出しで現在の目的地へ案内し、そこに再フォーカスする。タスクやルートは変更しない。

## 衣笠周辺での確認

参考位置 `35.0325428, 135.7240146` から、現データでは次の地点を選ぶ。

| 種類 | 地点 | 直線距離 |
|---|---|---:|
| コンビニ | 至徳館購買部 | 約111m |
| 公園 | 小松原児童公園 | 約416m |
| 駅 | 等持院・立命館大学衣笠キャンパス前 | 約523m |

実際のプレイヤーの位置で選択結果は変わる。現在のデータは全国をカバーせず、営業状況・入口・通路の正確さも保証しない。

## 確認方法

- `node scripts/verify-nearby.js`：実データの読み込みから衣笠・大阪の地点選択、駅までの進行、保存・復元、未掲載地域、範囲拡大、権限拒否、読み込み失敗・中止、小画面を確認。GPSと写真識別のみテスト用の応答を使用する。
- `node scripts/verify-classroom.js`：手紙と原地体験の既存の流れ。
- `node scripts/verify-play-modes.js`：スマホの選択復元、手紙完成から探索への引き継ぎ、原地体験の地図、明示的なモード変更時のルート維持。
- `node scripts/verify-before-play.js`：初回案内と権限設定。
- `node scripts/verify-exploration-sheet.js`：実在の天神橋筋六丁目駅の表示、パネルの開閉、マウス・タッチ操作、長文をスクロールした時の操作位置、通常の場面への復帰を確認。
- `npm run preview:mobile`：`screenshots/mobile-preview.html`。周辺探索はローカルのテスト位置を使い、既存の実データから地点を選ぶ。

### ローカルのテスト位置

`http://127.0.0.1:8000/?test=nearby`、またはテストメニューの「テスト位置 · 周辺探索」で、設定した位置から開始する。位置情報の許可は不要。手紙を書く画面など、ほかのテスト開始地点も引き続き使える。

位置はGit管理対象外の `test-location.local.json` に `{ "lat": 数値, "lng": 数値 }` として保存する。これはlocalhost専用で、公開版には含めない。ほかのテスト開始地点に移ると仮の位置を解除する。プレビュー生成時もこの設定を使い、設定がない環境では衣笠キャンパスの公開位置を使う。

OSM由来の地点データと地図の出典表示は維持する。地点ファイルを更新する場合は、出典・取得日・地域範囲も一緒に記録する。
