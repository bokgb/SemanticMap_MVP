# 言葉ハンター：7天主线与自由探索

这是在现有游戏上增加的七天故事版本。第1天的写信和送信保留，第2天帮助波可过小溪；第3～7天扩展为5个事件、40个环节，包含5次地图目的地确认、10次拍照传送、10次空间摆放、5次情境回应、5次短句组合和5封附照片的回信。实际游玩时长取决于阅读、寻找物品、拍照和步行；没有用等待倒计时延长时长。

| 天数 | 事件 | 主要操作与学习内容 |
| --- | --- | --- |
| 第1天 | はじまりの手紙 | 原来的拍照、写信与车站交付；完成后开放邮箱与自由探索 |
| 第2天 | 小川のむこうへ | 收到承接昨天物品的回信，拍照传送书／尺子、笔或叶子，走桥或坐船过小溪，寄出含照片的回信 |
| 第3天 | ポコの新しい仕事机 | 地图找到便利店场景；送书和笔；将书放在桌上、笔放在书的右边；写信 |
| 第4天 | ミナの小さなお茶会 | 地图找到便利店场景；送饮品和点心；练习桌上与杯子旁边；准备茶会并回信 |
| 第5天 | 公園に、ひと休みの場所を | 地图找到公园；送能做小长椅的书／椅子和花；练习树下与长椅左边；布置休息角 |
| 第6天 | 駅前の、小さな目印 | 地图找到车站；送站名牌与标记物；练习车站右边与邮筒前面；完成会合回信 |
| 第7天 | 七日目の、ありがとう | 地图找到公园场景；送喜欢的物品和花；复习右／左；办庆典、写一周回信并保留照片 |

第2天的来信由 Gemini 根据第1天物品生成；第3～7天使用人工编写的故事骨架并展示前一天保存的照片。新关卡的真实照片继续走现有 Gemini 识别接口，识别实际物品后显示日语名称和假名。文字、物品分类和位置规则有边界，不让 AI 编造真实地点或未实现的解法。

## 第2天：照片变成波可世界里的物品

本地入口：`http://127.0.0.1:8000/?test=day2`。点击“ポコのところへ”开始；也可从测试菜单重开本关。第一天流程没有改变。

- 来信：仅将第1天一件物品的名称发给现有 Gemini 接口，生成3行简单日语及中文。不会为了生成回信再次上传昨天的照片；来信缓存在本浏览器。识别服务不可用时，显示同样承接该物品的本地来信。
- 解法：书、笔记本、尺子或板变成平桥；笔、铅笔或筷子变成窄桥；叶子变成小船。这三种结果由人工设计，AI只负责把真实可见物品分类并给出物品名称，不产生未经实现的玩法。
- 操作：拍照或从相册选择 → 物品卡 → 点击传送 → 波可走过桥／乘船 → 生成本次经历的回信 → 玩家点击送出。只在最后送出回信后完成第2天，翌日开放第3天。
- 表现：保留玩家照片作为场景中的纸片物品，三条路径有不同对话和移动动画；减少动态效果设置下直接显示结果。已送出的方案保留在场景、回信和照片单词本中。
- 语言：保留物品名与假名、`橋を渡る`／`船に乗る`和短回信，不另加词语选择题或排序。
- 退路：提供本、笔、叶子的明确标注示例；本为原创插图，笔和叶子为已记录授权的照片。示例不会调用图像识别。取消、识别不匹配、接口失败均不消耗进度。
- 存档：新增 `kotoba-hunter-day-two-v1` 独立本地存档（测试入口使用独立 sessionStorage 命名空间）。不会覆盖第1天照片；存储不足时保留词语和步骤并提醒。重新开始只清除此游戏的存档。

本地测试若没有 `GEMINI_API_KEY`，可设置非秘密环境变量 `GEMINI_DEV_PROXY=https://semantic-map-mvp.vercel.app/api/gemini` 后运行开发服务，通过同一个项目的线上识别接口联调。不会把服务端密钥下发到浏览器，部署后的网页仍调用自己的 `/api/gemini`。

## 持续游玩规则

### 第3～7天的地图和位置练习

- 地图显示当前目标、已确认的当前位置及附近已收录的便利店／公园／车站。当前位置必须由浏览器定位得到；没有定位时不虚构“当前位置”，之前路线只明确作为参考显示。
- 步行模式下，地图打开时持续更新当前位置、方向与直线距离；页面切到后台或离开地图时停止定位监听，返回地图后重新连接。
- 使用现有 `spotsData.json` 的近邻搜索，不新增地图查询账号。默认3km，未找到目标时可以扩大至10km；即使另两类地点缺失，只要当天目标存在就能继续。
- 点击其他地点时提示当天目标，并把地图对焦回当天目标。只有选中目标后才开放步行模式的“已到达”按钮；到达由玩家确认，没有增加GPS围栏。
- 原地模式也显示地图；定位被拒绝、数据缺失或网络失败时，可以明确选择本环节原地继续，不会悄悄把原来的步行模式改掉。虚线与距离均标为直线参考，不生成或冒充实际步行路线。
- 位置练习发生在有明确参照物的波可场景里：上／下、左／右、旁边、前面。画面注明下方为前方。“旁边”接受左侧或右侧，不把同样合理的一侧判错。
- 照片放置后立即出现在场景中。每天最后寄出回信才完成当天，之后可重看两处摆放结果、照片与所写的信；第一天照片仍保留。
- 每天8个环节中，照片、位置、已选答案及回信选择均可刷新恢复。新增存档为 `kotoba-hunter-field-days-v1:3` 至 `:7`；测试使用隔离的会话存档。存储不足时保留步骤与词语并提醒。

主线须依次完成。下一封来信在上一次主线完成后的**下一个本地日历日**自然开放，不要求连续签到，也不会因晚来而扣分或失去已完成内容。切回网页或午夜到来时会检查新来信。送完第一封信后，玩家也可在自由探索地图上点击“次の日へ →”主动进入下一章，不必等待；线上和本地都可用。这个入口只在自由探索地图显示，正在做委托、领取奖励、写信、送信、邮箱和结束页都不显示。推进只解锁紧接着的一章，不伪造完成记录、不改变系统日期，也不清除已有照片。若该章已经开始，则显示“手紙のつづきへ”回到尚未完成的故事；七章全部完成后不再显示。

第1天通关后的第一次刷新／下次打开，会进入邮箱。后续任务的已选答案、组句、当前题目和完成邮戳都会保存在当前浏览器中。清除全部进度会同时清除7天存档；按钮的确认说明已更新。

目前日期以设备本地时间为准；修改系统日期可影响解锁，这一版没有做服务器校时。没有添加账号或跨设备同步。若浏览器不能保存，会显示保存提醒。

## 自由探索

每天主线完成后都能进入自由探索，邮箱入口也保留。新增独立的地图委托，不改变第1天路线或7天主线存档。

- 点击“現在地・委託を探す”，从现有导出地点数据中，按当前位置查找半径3km内的公开便利店、公园和车站。每类最多随机选择2处，共最多6份委托；有些类别没有数据时也能玩现有类别。无结果时可明确扩大至10km。没有虚构地点，也没有自动跳到OIC。
- 9种委托内容：便利店饮品／点心／写字工具，公园树／花／叶子，车站站名／旅途饮品／会合标记。照片继续经 Gemini 识别，显示实际物品的日语和假名、一个简短表达；示例不调用AI。
- 地图“！”和可滚动列表均能选择委托，选中后显示真实地名、内容与直线距离。步行模式必须有60秒内、误差不超过150m的定位，并进入目标150m内，才开放开始按钮；走出范围、定位过期或误差变大时重新锁定。开始拍照后不会因临时GPS变化中断任务。到达判定不等于实际道路导航。
- 定位监听仅在地图打开且页面可见时运行。切到后台或开始任务即停止；回来后重新检查。已完成的委托显示勾号，照片和词语进入照片单词本。最近50份照片记录保存在当前浏览器，今日完成数单独累计；不上传照片或坐标到研究后台。
- 随机委托、选中地点、识别后的奖励均保存；普通刷新和重新定位不会重抽已有委托。“別の委託を探す”才主动换一组；跨天回到地图时生成新的一天。任务跨过午夜时，先保留正在完成的任务。
- 原地体验有明确标签，可以跳过距离要求。没有定位或地点数据时提供3份不指定真实地点的练习委托，不伪造地图标记，也不更改主线的体验方式。相册、示例、权限帮助和返回邮箱入口保留。
- 存档使用 `kotoba-hunter-free-map-v1`，本地测试另用隔离的会话存档；存储不足时保留词语和进度并提示。游戏重新开始只清除此游戏的存档。

## 与现有研究统计的边界

现有 Supabase 试玩记录和问卷编号仍沿用，不上传照片。现有后台的“完成阶段数（共4项）”继续表示第1天写信、便利店、公园和车站交付，**不把它当作7天完成数**。本次新增的后续天数、答案与自由委托记录目前只保存在浏览器；尚未接入云端的纵向研究统计。正式进行7天研究前，需要单独扩展每日统计与分析方案。

## 检查

`node scripts/verify-day-two.js` 覆盖第二天三种过河方式、缓存来信、上传、错误与取消、示例退路、照片恢复、场景与单词本、完成时机和次日锁定。`node scripts/verify-seven-days.js` 覆盖第3～7天40个环节、位置选择与刷新、场景回顾，以及日历、自由探索和原存档的回归。`node scripts/verify-field-map.js` 用模拟定位配合真实已导出地点数据，验证当前位置、目标选择和对焦、320px固定控制区、识别上传数据流、刷新、权限拒绝退路及重新开始。另用真实 Gemini 识别了可乐照片并完成摆放。手机相机授权与真实户外步行仍需实机验证。

`node scripts/verify-free-explore.js` 覆盖真实候选地点、随机委托稳定存档、GPS进入／离开范围及精度限制、选中目标恢复、照片API与奖励恢复、原地示例、完成后回地图与照片本、跨天更新、320px固定控制区、拒绝定位／空地点数据退路及独立重置。定位由浏览器测试环境模拟，不能代替真实手机的步行测试。

自由探索另做了一次真实 Gemini 请求：使用面包照片完成点心委托，接口返回200、日语名称「パン／ぱん」，奖励可以正常送出并返回地图。
