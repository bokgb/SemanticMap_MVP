# 试玩数据

后台：https://supabase.com/dashboard/project/lzjbxukiptyyzebbvrro/editor

用 bokgb's Org 所属账号登录，打开 Table Editor，在表／视图列表中选择 **play_summary**。这里是正式试玩的中文汇总，可以导出 CSV。本地测试记录不会出现在这个视图中。玩家需要在新版游戏的开始说明中同意记录，后台才会收到这次试玩的数据。

## 记录内容

| 项目 | 含义 |
| --- | --- |
| 试玩编号 | 每次旅程自动生成，例如 KH-012345ABCDEF；不是姓名或登录账号 |
| 最后进度 | 开场、写信、出发、便利店、公园、车站、完成交付 |
| 完成阶段数 | 共4项：写完信、便利店补给装包、公园任务、车站交付 |
| 前台游玩分钟 | 网页可见的累计时间；切到后台时暂停，通关后停止。包含阅读、等待等时间，不等于专注时间 |
| 起止经过分钟 | 从开始到结束／最后一次收到记录的经过时间，可能包含离开网页的时间 |
| 探索方式 | 原地体验或走路探索；显示最后选择的方式 |
| 打开过问卷 | 只代表点击过问卷链接，不能据此认定已提交问卷 |

不上传照片、拍照次数、识别文字、位置、路线、姓名或设备指纹。游戏本身的拍照识别及浏览器内进度保存仍按开头说明运行。

首次开始时，玩家自行勾选“研究への協力（任意）”才上传上述记录。不勾选也能正常游玩。旧版玩家没有同意记录时，不补采历史数据。

刷新沿用同一试玩编号，重新开始生成新编号。已上传的旧旅程不会因玩家重新开始而删除。同一位玩家多次重玩会有多条记录，不能直接把记录数当作人数。

## 与问卷对应

最后在车站交付后点击问卷，**R02 参加者コード**自动预填同一个试玩编号，不用玩家手输。

回答表格：https://docs.google.com/spreadsheets/d/1z6QpQXjbb0Yl8KiY5sf3Qdk_1XoqD-hLmeT5DcPfsFk/edit

把后台 CSV 的“试玩编号”与回答表格 R02 列对应，即可比较体验记录和问卷回答。问卷回答仍保存在 Google Sheets，不会自动复制到 Supabase。Google 表单的预填编号可以被玩家修改；配对时应检查空值、重复值和不匹配的编号。

## 数据限制

阶段改变时会保存，游玩中约每15秒更新。断网时先在浏览器保存，联网或重新打开后重试；不能保证用户永久离线、清理浏览器数据或突然关机前的数据都能上传。关闭网页后不会继续追踪。

本地普通网址 `/` 可测试记录，数据标记为 is_test；`?test=...` 和 `?preview=...` 演示入口不上传、不修改正式研究记录。后台原始表 play_sessions 供排错，研究分析优先看 play_summary。

后台只允许所有者查看；浏览器只能使用自己的随机旅程写入凭据更新该旅程，无法读取其他玩家记录。免费项目没有开启付费升级。

## 后台检查记录

2026-10-22：实际接口验证了创建、完成4项、旧请求重试不会覆盖新进度、错误写入凭据被拒绝、包含照片字段的请求被拒绝。普通公开角色没有表读取和数据库写入函数权限。

安全检查没有警告或错误。`RLS Enabled No Policy` 是信息提示：研究表刻意不允许公开客户端直接读写，只有服务器能操作（[官方说明](https://supabase.com/docs/guides/database/database-linter?lint=0008_rls_enabled_no_policy)）。新建的最后更新时间索引暂未使用，也属于信息提示（[官方说明](https://supabase.com/docs/guides/database/database-linter?lint=0005_unused_index)）。
